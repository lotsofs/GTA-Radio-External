| 2026-11-03 | VDT | Games | Let game files list version signatures, so a file used on another version says so and lets the music play instead of reading the wrong address, and give the San Andreas 1.0 files theirs | A file had one offset for every version, so another version read whatever was there. | 2026-11-03 | HWN | Music players | Find the player's window when sending, so a window that appears late or is recreated is still muted, and declare window handles as `IntPtr` | The window was looked up once, 3 seconds after the process started, so a later or replaced window got nothing while the status said `Running`. It's now looked up whenever there's none or it's gone, and a missing one shows as an error that the next poll retries. Verified with the built tool and stand-ins: the old build never muted a player whose window came 8 s late, and lost one whose window was recreated; the new one handled both, and module lookup gives the same bases as `Process.Modules`. |
| 2026-11-03 | RDF | Memory | Leave the music as it is when the game's radio or the player's volume can't be read or isn't known, and say so in the status | Failed reads passed for 0 or made-up values, so an unreadable address or an unlisted radio value muted the player, and a read toggle could invert it. Reads now throw on failure: an unreadable or unknown radio leaves the player alone, and a failed volume read touches nothing and retries. Verified with the built tool and stand-ins on unreadable addresses and an unknown value: the old build muted or inverted the player in all four scenarios, the new one in none. The full hook matrix was stopped after 19 passing scenarios. |
| 2026-11-03 | VAL | Config | Check game and music player files when they're picked, and say what's wrong instead of crashing or failing in the poll | Files were deserialized unchecked, so a bad one crashed the window or failed later in the poll; one load step now reads, checks and parses each file, and a failed pick names the field and keeps the loaded file. Verified with the built tool and stand-ins: the old build crashed on a bad player file and stopped following the radio after a bad game file, while the new one shows the problem and keeps working, and the hook matrix still passes all 64 scenarios. |
| 2026-11-03 | SYN | Radio | Keep the music player in step with the radio from the start, and restore it when the game or the tool closes or another player is picked | `Radio` only acted on radio changes while the game ran. It now tracks what it last told the player, counts no game as radio on, restores the old player before swapping, and leaves a new player process alone for 3 seconds, so a toggle can't be lost. Verified with the built tool, a stand-in game and stand-in players on every hook: the old build failed 54 of 64 scenarios and the new one none. The `AudioSession` hook also passed on real WACUP; not yet seen with a real game. |
| 2026-11-03 | FOB | Music players | Accept a quoted hex `addressOffset`, so `Foobar2000.json` loads | The file quotes its offset, which an `int` field couldn't read, so a small converter now reads numbers and `0x` strings for games and players alike, leaving the file unchanged.
